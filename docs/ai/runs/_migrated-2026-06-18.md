**End-to-end smoke + real bug surfaced** [`ebd4d95`]
- `tests/smoke/test_practice_end_to_end.py` exercises six full pipeline scenarios with mocked synth + real Qt timers + in-memory MIDI files: free-mode note emission, waiting-mode pause/resume on HIT, MISS red-flash + auto-clear, mute suppression, `song_finished`, plus two more `_artifacts/` screenshots (`practice_mid_playback.png`, `practice_waiting_amber.png`).
- **Bug found:** `QComboBox.currentTextChanged` does **not** fire when `setCurrentText()` is called with the value already selected. The Mode combo defaults to "Waiting" but `MidiFilePlayer` initialises to "free", so the underlying mode was wrong until the user manually toggled the combo. Caught by waiting on the `waiting_for` signal with `qtbot.waitSignal` and timing out — the unit test had bypassed this by calling `set_mode` directly.
- **Fix:** explicit `self._player.set_mode(self._mode_combo.currentText().lower())` at the end of `PracticeWindow.__init__`. Regression test `test_player_mode_matches_combo_default_on_init` added.

### 2026-06-11 — Qt headless test suite runnable on macOS (offscreen→minimal fallback)
3 commits making the documented verification command pass on macOS.
- **Root cause** [`25e5903`] — the documented verification command (`QT_QPA_PLATFORM=offscreen pytest -v`) segfaulted (Bus error) on macOS whenever a `QMainWindow` is shown or grabbed, hitting `PracticeWindow` screenshot/open smoke tests (`test_window_screenshot_offscreen`, `test_practice_button_opens_window`, `test_free_mode_playback_emits_practice_notes`). - **Fix** [`25e5903`] — `tests/conftest.py` now transparently falls back `offscreen→minimal` on Darwin (override with `SOUNDPAD_KEEP_QT_PLATFORM=1`); Linux keeps `offscreen`. Result: **102/102 pass on macOS** via the documented command.
